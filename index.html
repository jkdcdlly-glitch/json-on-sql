Hands-on Guide: Query & Export JSON with SQL — Skip the Throwaway Scripts

In day-to-day development we constantly need to inspect huge JSON files returned by third-party APIs, or extract key fields from scraped JSON data. The traditional approach is to throw together a temporary Python/Node.js script, or import everything into MySQL/MongoDB — both slow and tedious.

This guide shows you how to use this fully client-side tool to query JSON directly with SQL syntax — just like working with a database — and turn it into an Excel / CSV table in one click.

1. Core Workflow: Query JSON with SQL

When you select an array node on the left (typically a result or data array), the SQL editor automatically appears above. The built-in lightweight SQL engine covers most of the queries you need day to day.

1.1 Basic extraction: SELECT

Suppose your JSON data looks like this:

[
  { "id": 1, "name": "Alice", "role": "admin", "age": 28 },
  { "id": 2, "name": "Bob", "role": "user", "age": 34 }
]

Usage: no need to pull every redundant field — just name the columns you want with SELECT:

-- extract name and role only
SELECT name, role FROM data;

1.2 Conditional filtering: WHERE

To filter out specific rows, use a WHERE clause. Standard comparison operators are supported: =, !=, >, <, >=, <=.

-- users older than 30
SELECT name, age FROM data WHERE age > 30;

-- admins only
SELECT * FROM data WHERE role = 'admin';

1.3 Fuzzy matching: LIKE

When you need to search for content containing a specific keyword, LIKE is your best friend. Use % as a wildcard for any characters.

-- names starting with 'A'
SELECT * FROM data WHERE name LIKE 'A%';

-- emails containing 'gmail'
SELECT * FROM users WHERE email LIKE '%gmail%';

1.4 Combining conditions: AND / OR

You can combine multiple filter conditions with AND and OR.

-- older than 25 AND role is admin
SELECT * FROM data WHERE age > 25 AND role = 'admin';

1.5 Sorting results: ORDER BY

If the data is in no particular order, use ORDER BY to sort ascending (ASC, the default) or descending (DESC).

-- by age, largest first
SELECT * FROM data ORDER BY age DESC;

-- by role ascending, then age descending
SELECT * FROM data ORDER BY role ASC, age DESC;

1.6 Pagination: LIMIT & OFFSET

Facing thousands of rows? Preview just the first few. OFFSET lets you emulate pagination.

-- first 10 rows only
SELECT * FROM data LIMIT 10;

-- skip 20, take the next 10 (page 3)
SELECT * FROM data LIMIT 10 OFFSET 20;

2. Exporting JSON to Excel or CSV

Deeply nested JSON is painful to read. Flattening it into a table is the most direct way to analyze it. This tool ships a complete "JSON to Excel" pipeline:

2.1 Auto-generated tables

Click an array node that contains multiple records on the left, and the right panel automatically detects its structure and renders a data table. No matter how many fields there are, you can scroll horizontally to see them all.

2.2 Pick your columns

JSON often carries dozens of fields when you only care about four or five. Click the ⚙️ Columns button above the table and check the fields you need. This is essential for keeping wide tables readable.

2.3 Copy or download in one click

Once filtered, use the toolbar buttons:

  • 📋 Copy (TSV): data is copied to the clipboard tab-separated. Open Excel and paste (Ctrl+V) — every value lands perfectly aligned in its own cell.
  • ⬇️ CSV / TSV: need a file to send to a colleague? Hit download to get a standard spreadsheet file.

2.4 Why exported spreadsheets never show garbled text

A classic problem: export a CSV, open it in Excel, and every non-ASCII character turns into mojibake. Plain UTF-8 encoding lacks a BOM header. This tool automatically prepends a BOM marker (\uFEFF) when generating files, so Excel reliably detects UTF-8 encoding — garbled text is gone for good.

3. Advanced: Deep Nesting & Obscure Fields

3.1 Unlimited depth & huge-file support

If your JSON is deeply nested, the tree on the left expands on demand. Even with thousands of items in an array, the tool renders only 200 at a time and offers a "▼ Load more" button at the bottom. This lazy-rendering mechanism keeps the browser responsive no matter how big the file is, with memory usage staying extremely low.

3.2 One-click locate & search

Spot a strange error code or number on screen (say 47754) and want to know where it lives in the JSON? Type it into the search box on the left. The tool instantly scans the entire JSON and lists every matching path (e.g. $.result[728].organicTraffic). Click a result to jump straight to the node and highlight it.

3.3 AI-powered field translation

Inherited someone else's system, or scraped a foreign API? Staring at fields like intentCommercialPositions or serpFeaturesTrafficCost is brutal.

This tool ships with a built-in glossary. For anything it does not know, click ✨ AI (top-left) and configure your own API key (DeepSeek, ChatGPT, etc.). AI identifies all obscure business terms within seconds and names them in plain language — cached in your browser permanently, hugely improving reading efficiency.

4. FAQ (Frequently Asked Questions)

My JSON file is tens of MB. Can this tool open it? Will it freeze?

No freeze. Naive formatters try to render every DOM node at once and crash the browser with memory exhaustion. This tool renders only the nodes currently in view or expanded, so even huge files open smoothly.

Does the SQL engine support JOIN or GROUP BY aggregates?

Not yet. To keep the engine lightning-fast and purely client-side, it focuses on core single-table queries (SELECT, WHERE, ORDER BY, LIMIT). Multi-table JOIN and SUM/COUNT aggregates are not supported yet — export the query result and aggregate in Excel.

My JSON contains company secrets or user privacy. Is it safe?

Absolutely safe. This tool runs purely in the browser with no backend server. All parsing, querying and exporting happen locally in your own browser (JavaScript engine). You can open the DevTools network panel or even disconnect from the internet and keep using it — no data is ever sent anywhere.

My JSON has a syntax error and refuses to parse. What now?

On import, the tool reports the exact location of the syntax error (line, column, missing comma, etc.). If data is already loaded, click "📝 Edit JSON" on the left, fix the text in the dialog, and hit apply to re-parse.
